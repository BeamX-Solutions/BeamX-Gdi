# DB

## Overview

The data layer: Drizzle ORM 0.45 on Neon Postgres (Frankfurt) through the `neon-http` driver, the schema and its migrations, and the typed query layer every route, Server Action, `assistant/`, and `auth/` call into. Spec 0002 is the contract.

## Key files

| Path              | Owns                                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `client.ts`       | The one `db` instance (`drizzle(neon(env.DATABASE_URL))`)                                                                                          |
| `id.ts`           | `newId()`, UUID v7, the id helper for every app table and the AI SDK `generateId`                                                                  |
| `errors.ts`       | `isUniqueViolation(e, constraint)` for mapping Postgres `23505` to typed errors                                                                    |
| `schema/`         | One file per domain (`chat.ts`, `runs.ts`, `usage.ts`), re-exported from `schema/index.ts`; `auth.ts` is generated by Better Auth, never hand edit |
| `migrations/`     | Generated SQL plus drizzle meta; never hand edit                                                                                                   |
| `queries/`        | The query layer: `conversations`, `messages`, `runs`, `reports`, `usage`, `users`                                                                  |
| `test/helpers.ts` | Integration test helpers: `guestTracker`, `runWithAnswers`, `completeFromAnswers`, `unwrap`                                                        |

## Commands

```bash
pnpm db:generate        # write a migration after any schema change, then commit it
pnpm db:migrate         # apply migrations (uses DATABASE_URL_UNPOOLED)
pnpm db:check           # migrations folder consistency only, NOT schema drift
pnpm test:integration   # *.int.test.ts against a real Neon branch
```

## Conventions

- Every user facing query takes the session `userId` and filters by it; another user's row returns a typed `not_found`, never data. Expected outcomes return `Result` (`@/lib/result`); only infrastructure failures throw.
- Keep each call to one round trip: multi step writes are one `db.batch` of independent statements (`neon-http` has no interactive transactions). Concurrency is enforced in SQL (row locks, compare and set, the partial unique index), not in app code.
- Writes that finish after a guest link (`onFinish`, the report step) get the owner from `conversations.ownerOf` or `runs.ownerOf`, never from the session captured when the stream started. Both are server only.
- Every new user owned table must be added to `users.linkGuest` and given a delete rule (cascade, or SET NULL for business records). `link.int.test.ts` reads every foreign key to `user.id` and fails on a table that is neither linked nor excluded.
- Schema changes are additive only (spec 0002, AC-12): new tables, nullable columns, foreign keys, enum values. Anything else goes back through `/architect`.
- Timestamps use `mode: "string"`. Pass them back as the raw strings (for example `lastAnswerAt` to `runs.complete`); a JS `Date` drops the microseconds and breaks the answer fingerprint.
- Hand written SQL goes through Drizzle's `sql` template with bound parameters, never string concatenation.

## Testing

- Integration tests (`*.int.test.ts`) run against a throwaway Neon branch, never `production` or `dev`. CI creates and deletes one per PR. Locally, export the branch's `DATABASE_URL` and `DATABASE_URL_UNPOOLED` before running; exported vars win over `.env`.
- Each test file owns its users through `guestTracker()` and cleans up by deleting them (the cascade removes their rows), so files can share one branch.

## Gotchas

- `drizzle-kit check` never compares the schema to the migrations. CI catches drift with a separate step: `pnpm db:generate`, then fail if `src/db/migrations` changed.
